## 2. E1 推理冒烟（作业 441290，sbatch；约 0.17 GPU h）

- 合成 v2 的前 5 个 dev 主集基础场景，含两张孪生图，共 15 张图，每个模型 90 条。题型：框（两个物体）、同轴二选一 × 2 种顺序、成对二元。
- 5 个适配器：Qwen2.5-VL、Qwen3-VL、Qwen3.5-2B、InternVL3-8B、GLM-4.6V-Flash。框、二选一、二元的解析率都是 100%；预测框的原图坐标和直接回答的 fp32 选项 logprob 都存下了。
- 没跑的 6 个模型与已测适配器的对应：RoboBrain2.0 → Qwen2.5-VL；InternVL3.5、SenseNova-SI-1.2、SenseNova-SI-1.3 → InternVL3；Qwen3.5-4B、Qwen3.5-9B → Qwen3.5-2B。
- **GLM 的问题**：GLM 的选择题答案方式是 text64（先推理、最后给字母），所以**首步 logprob 不是答案的 logprob**（冒烟里 A、B 两项是 −16.1 / −12.6）。方案 A 要的 logit 差 L，对 GLM 必须在答案字母所在的那一步取。其余 4 个适配器首字作答，首步 logprob 就是答案的。需要 planner 决定（见第 6 节）。

## 3. 备选判定方案（代码：`src/e1_alt.py`；`configs/e1.yaml` 的 `alternatives`）

- **A 连续量耦合**：L ~ 自然样条(log2 真实距离, 4 结) + β·(Δ̂ − Δ)，按场景 bootstrap β 的 CI。
  - H1 / H2 的“判对” = β 的 CI 下界 > 0；H3 的“判对” = β 的 CI 包含 0。
  - 另报等价判定：标准化效应 β·sd(Δ̂ − Δ) / sd(残差) 的 CI ⊂ (−0.1, 0.1)。
- **B OR 限定范围**：只在 dev 上框推正确率 ≤ 0.9 的档里算按档分层的 MH OR；任一格期望 < 5 的档不用；一档不剩就记“不可估”。另报按档分层的条件最大似然 OR（似然比 CI），只用顺序 0。
- **C 比值限定条件**：θ_IO 的 bootstrap CI 完全落在该模型的采样距离范围内才做比值判定，否则“不适用”，改报每档直接回答与框推的正确率差（配对，McNemar 精确检验）。
- 另加档内连续距离的 logistic 回归：直接回答对错 ~ 样条(log2 距离) + 框推对错。
- 模拟智能体（`src/e1_sim.simulate_L`）：每个条目一个内部决策量 S，两个顺序共用；每个顺序 L = κ·S / sd(e_t − e_r) + ν，κ = 3，ν ~ N(0, 0.5)；回答 = L 的符号。
  - H1：S = Δ̂；
  - H2：S = 量化到 0.5 token 的 (d + 0.5·(e_t − e_r))，即更粗、更少噪声、与框误差部分相关，所以 H2 的“判对”在 A、B 下也是“相关”；
  - H3：S = d + 另抽的独立误差。

### 4.2 结论（如实）

1. **合成集上的框误差同样很小。** 多数模型的中位绝对误差是 0.01–0.05 token，和 What's Up 同一个量级；只有 RoboBrain（约 0.1–0.18）和 InternVL3、SN-1.2、SN-1.3 的小尺寸档（0.1–0.55）大一些。所以第一版的结论（天花板）不是 What's Up 物体太大造成的。
2. **原判定、B、C 在 11 个模型上基本都用不了。**
   - B 几乎全部不可估：框推正确率 ≤ 0.9 的档几乎没有。
   - C 几乎全部不适用：θ_IO 的 CI 不在采样距离范围内。只有 SN-1.3 的 C 适用率达到 0.9 以上，但判对率只有 0.2–0.4。
3. **A 在 H3 下稳定。** “β 的 CI 包含 0”的比例是 0.90–0.97，等价判定在多数模型上 0.79–1.00（RoboBrain 只有 0.03：它的误差大，标准化效应的 CI 宽）。
   - **A 在 H1 下分化**：RoboBrain 0.99、InternVL3 1.00、SN-1.3 1.00；InternVL3.5 0.59、GLM 0.52、SN-1.2 0.37；Qwen2.5-VL、Qwen3-VL、Qwen3.5 系列只有 0.10–0.29。
   - 原因：这些模型的框误差太小，L 里由框误差带来的变化（标准化效应约 0.01–0.05）被假设的读出噪声 ν 淹没。
4. **A 的 H1 功效依赖两个没有实测依据的模拟参数**：κ（L 随决策量变化的强度）和 ν（L 的读出噪声），而且 L 按 sd(e_t − e_r) 标准化，误差池里少数离群值会把 sd 抬高。真实模型 L 的噪声有多大，可以用冒烟里已存的 fp32 logprob 在 dev 上估。这一步还没做。

## 6. 需要 planner / Xiwei 决定

1. **GLM 的 L 怎么取**：建议在生成序列里定位最终字母所在的那一步，取该步的 fp32 logprob（只改记录方式，不改提示和解码），正式运行前在 dev 上验证。
2. **方案 A 的模拟参数**：要不要先用 dev 上的真实 fp32 logprob（冒烟的 5 个模型，或者另做一个更大的 dev 子集，需要 GPU）估出 L 的读出噪声，再重做 A 的功效？这决定 A 对 Qwen 系列有没有用。
3. **单物体检查不通过的尺寸档**：要不要按排除后的条目重跑功效模拟（只影响 InternVL3、SN-1.2、SN-1.3、Qwen3.5-2B）？
4. 基于以上，预注册第 4 节的判定规则怎么写：原判定、B、C 在现有距离设计下基本都不适用；A 在 H3 下可用，在 H1 下对多数模型功效不足。
